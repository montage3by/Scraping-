# Plan: Программа запуска — бесплатный продукт (сбор email) → реклама → Repas (платный SaaS)
**Research:** thoughts/research/2026-08-26-full-program-replan.md
**Status:** planning
**Старт:** 1 сентября 2026

## Challenge Log

**Problem:** Нужен план на три вещи сразу — бесплатный продукт для сбора email, реклама этого продукта, и полноценный платный SaaS Repas — с точкой отсчёта 1 сентября.

**Chosen solution:** Последовательно-пересекающиеся фазы с общим фундаментом
(коллекторы данных), а не три независимых параллельных трека с 1 сентября.

**Alternatives considered:**
1. **Всё три трека параллельно с 1 сентября** — отклонено: и бесплатный продукт, и Repas опираются на один и тот же код сбора данных (`collectors/`), который ещё ни разу не проверялся на реальной сети. Строить их параллельно значит писать/чинить одну и ту же инфраструктуру в двух местах одновременно.
2. **Сначала полностью Repas (8 недель по PRD), бесплатный продукт — потом** — отклонено: бесплатный продукт готов на ~80% прямо сейчас, задержка его запуска ради параллельной разработки Repas не даёт видимого результата (лидов/email) ещё 2 месяца без причины.
3. **Только бесплатный продукт, Repas отложить на неопределённый срок** — отклонено: у вас уже есть проработанный PRD 3 раунда ревью, откладывать его старт без даты обесценивает уже сделанную работу по нему.

**Why chosen solution is better:** Бесплатный продукт первым выходит в публичное поле — даёт лиды и служит живым тестом инфраструктуры сбора данных на реальном сервере. Repas стартует не позже чем через 2-3 недели, уже на стабилизированном фундаменте — быстрее и надёжнее, чем с нуля.

## Phase 1: Фундамент — бесплатный продукт на реальном сервере
**Даты:** 1–7 сентября
**Status:** pending
**Файлы:** деплой существующего кода (`backend/`, `collectors/`, `report/`, `landing/`) — новый код в этой фазе в основном чинит, а не пишет с нуля

**Изменения:**
- Развернуть backend + worker + лендинг на VPS (Docker или напрямую)
- Прогнать `google_maps` и `google_news` коллекторы на реальной сети, поправить селекторы/логику по фактическому результату (ожидаемо: понадобится правка, ни разу не проверялись вживую)
- Подключить `RESEND_API_KEY`, проверить реальную доставку письма с вложением
- Проверить PDF-конвертацию (docx→pdf) на сервере — в песочнице разработки не работала из-за ограничения самой песочницы, на сервере ограничения нет
- Мягкий запуск: рабочая публичная ссылка на квиз, реальный сквозной прогон на 1-2 живых ресторанах

**Gates:**
- [ ] Заявка через публичный лендинг доходит до письма с реальным содержимым (не dry-run)
- [ ] Хотя бы 1 из 2 существующих коллекторов реально возвращает отзывы, а не просто не падает
- [ ] Полный цикл (квиз → письмо) укладывается в заявленные ~10-15 минут

**Impact:** Затрагивает только деплой существующего кода, риска для других модулей нет — это первый раз, когда код вообще встречается с реальной сетью.

**Prompt for launch:**
```
Read plans/2026-08-26-repas-program-plan.md, Phase 1.
Сервер уже поднят и доступен по SSH.
Задача: задеплоить backend/worker/landing, прогнать google_maps и
google_news коллекторы на реальной сети, починить что сломается,
подключить Resend, проверить PDF-конвертацию, сделать мягкий запуск.
Не трогать collectors/registry.py сверх добавления рабочих исправлений
в google_maps.py/google_news.py.
```

## Phase 2: Расширение источников + запуск рекламы бесплатного продукта
**Даты:** 8–21 сентября (2 недели)
**Status:** pending
**Файлы:** `collectors/tripadvisor.py` (новый), 1 delivery-коллектор на выбор (новый), `collectors/registry.py`

**Изменения:**
- Добавить 2-3 новых коллектора по приоритету реального спроса (рекомендация: Tripadvisor — универсален для всех регионов; один delivery-сервис — начать с Wolt, он подтверждён почти во всех сконфигурированных странах)
- Запустить канал продвижения бесплатного продукта (см. открытый вопрос ниже — без ответа пользователя эта часть не может быть спланирована конкретно)
- Начать копить базу email через реальные заявки

**Gates:**
- [ ] Новые коллекторы проходят тот же паттерн, что google_maps.py (try/except → `CollectionResult`, никогда не падают наружу)
- [ ] Отчёт с 3-4 источниками не превышает заявленные ~10-15 минут по времени сборки (проверить на реальных данных, не только мок)

**Impact:** Расширяет `collectors/registry.py` — не меняет уже работающие google_maps/google_news.

**Prompt for launch:**
```
Read plans/2026-08-26-repas-program-plan.md, Phase 2.
Реализуй collectors/tripadvisor.py и collectors/wolt.py по образцу
collectors/google_maps.py (тот же интерфейс PlatformCollector,
try/except внутри, никогда не бросать исключение наружу).
Зарегистрируй оба в collectors/registry.py.
Проверь на реальном сервере (не в песочнице), поправь селекторы по факту.
```

## Phase 3: Repas — платный SaaS по существующему PRD v1.2
**Даты:** с ~22 сентября (после стабилизации фундамента фаз 1-2)
**Status:** pending
**Файлы:** согласно PRD v1.2, раздел 12 (полный 8-недельный роадмап), начиная с недели 1

**Изменения:** Полный роадмап уже прописан в PRD Repas v1.2 (3 раунда ревью, актуален) — эта фаза лишь **сдвигает точку отсчёта** его "недели 1" на ~22 сентября вместо буквально 1 сентября, потому что PRD-шная "неделя 1" (онбординг + PostgreSQL + layout) логически идёт после того, как коллекторы уже работают на реальном сервере — а не до.

**Ключевое отличие от PRD "как есть":** в PRD недели 5-6 месяца 2 — это "добавить TripAdvisor/Wolt/2GIS коллекторы". В этом плане они уже будут сделаны в Фазе 2 — значит реальный Repas-роадмап **короче на ~2 недели**, чем в PRD, потому что часть его работы уже выполнена заранее в рамках бесплатного продукта.

**Gates:** согласно PRD v1.2, раздел "Deterministic Gates" (tsc/pytest/lint/ruff по мере появления кода)

**Impact:** Новый код (Next.js/FastAPI-дашборд, PostgreSQL) — не пересекается с существующими `collectors/`/`report/`/`backend/` модулями напрямую, но **переиспользует** их как библиотеку.

**Prompt for launch:**
```
Read plans/2026-08-26-repas-program-plan.md, Phase 3, and the full
Repas PRD v1.2 (найти в переписке/приложенных файлах пользователя).
Начни с недели 1 PRD-роадмапа, но пропусти повторную реализацию
коллекторов TripAdvisor/Wolt/2GIS — они уже есть из Фазы 2, просто
подключи их в новую архитектуру (venue_platform_ids и т.д.).
```

## Открытый вопрос (требует ответа пользователя, не решается кодом)

**Реклама/продвижение бесплатного продукта** — в разговоре не определены ни канал
(таргет в соцсетях, прямой аутрич владельцам ресторанов, партнёрства), ни бюджет,
ни кто это делает физически. Без ответа Фаза 2 не может получить конкретные сроки
и стоимость по этой части — сейчас в плане она обозначена как "запустить", но не
как "как именно".
