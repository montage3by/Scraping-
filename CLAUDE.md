# CLAUDE.md — правила работы с агентом

## Что это за проект

**Daily Yolk** (рабочее название, переименовывается с Repas) — сервис мониторинга репутации ресторанов и кафе. Два уровня: бесплатный MVP-лид-магнит (лендинг → email-разбор репутации и конкурентов) и платный SaaS Daily Yolk (подписка, отдельный PRD).

Гео: Кавказ, Средняя Азия, Европа — сознательно не Россия.

Подробности — в `.business/INDEX.md`.

## Структура репозитория

```
./

│   ├── INDEX.md              ← оглавление, входная точка
│   └── company/ products/ audience/ goals/ economics/ marketing/ assets/ execution/
```

## Планирование — методология Bulletproof

Технические планы ведутся **не** по общему шаблону `plans/YYYY-MM-DD-название.md` из стартера, а по уже установленной методологии **Bulletproof** (`.claude/skills/bulletproof`): Challenge Log, таблица Problems, фазы со статусом/Gates/Impact, сопроводительный ресерч в `thoughts/research/`.

Актуальный план запуска — `plans/2026-08-26-repas-program-plan.md`. Перед новой крупной задачей — сверься с ним, не создавай параллельный план в другом формате.

## Стек

Python 3 / FastAPI backend, SQLite очередь задач, Playwright-коллекторы (16 площадок: Google Maps, Tripadvisor, Wolt, Glovo, 2GIS, Яндекс.Карты, Yelp, TheFork и др. — часть с реальными API, часть браузерными заготовками, часть честно помечена «нужен ресерч»), генерация отчёта docx→PDF, доставка через email (Resend) и Telegram, Docker/docker-compose, pytest + GitHub Actions CI.

## Ключевые принципы работы

1. **Всегда читай `.business/INDEX.md`** перед задачей, связанной с бизнесом, текстами лендинга, маркетингом. Не придумывай позиционирование без контекста — многие блоки помечены TBD, уточняй у пользователя, а не выдумывай.
2. **Один чат — одна задача.** Закончил — закрой чат, открой новый.
3. **Ищи в `prompts/INDEX.md`** до того как писать промпт с нуля.
4. **Планы — через Bulletproof** (см. выше), не через отдельный шаблон стартера.
5. **Ретроспектива в конце каждой сессии** — в `retrospectives/YYYY-MM-DD_HH-MM_название.md` по формату из `retrospectives/TEMPLATE.md`.
6. **Перед push** — прогони `pytest` и линтер. 89 тестов уже есть, не должно становиться меньше без причины.
7. **Коммить только свои изменения.** Не используй `git add .` / `git add -A` в обычной работе — стейджь файлы поименно.
8. **Коллекторы, помеченные «нужен ресерч»** — не угадывай селекторы. Либо делай реальный ресерч, либо оставляй помеченным как есть.
9. **Данные с коротким TTL** (цены, лимиты, даты кампаний) — в конфиге/БД, не хардкодить в коде.

## Безопасность

- **Не скармливай Клоду:** пароли, приватные ключи, ПДн пользователей рестораций/клиентов.
- **`.env` не читай целиком** — только через `grep "^VAR_NAME=" .env` по конкретной переменной.
- **Перед включением Bypass Permissions** — обязательный git-коммит.
- **Запреты в `.claude/settings.json`:** `rm -rf`, `curl` с `export`, чтение `.env`, `wget` с переменными, `chmod 777`.
- **Перед установкой любого скила или MCP** — аудит через `prompts/setup/08-skills-install.md`.
- Проект уже прошёл security-review (см. историю сессий) — не понижай планку при новых изменениях, особенно в `backend/` и коллекторах, которые ходят во внешние API/сайты.
