# Задача на ресерч: площадки для публикации статей по гео — проект Repas

Скопируй этот файл целиком в начало новой сессии. Ниже — весь необходимый контекст, доступ к репозиторию проекта не требуется.

## Контекст проекта

Repas — сервис мониторинга репутации ресторанов/кафе в интернете (собирает упоминания
и отзывы с карт, отзовиков, приложений доставки и соцсетей). Сначала запускается
бесплатный лид-магнит (разовый отчёт о репутации на email через квиз-форму), позже —
платный SaaS-дашборд с ежедневным автообновлением.

**Целевые рынки — не Россия:**
- **Закавказье**: Грузия, Армения, Азербайджан
- **Средняя Азия**: Казахстан, Узбекистан, Киргизия, Таджикистан, Туркменистан
- **Европа**: Западная (Германия, Франция, Испания, Италия, Нидерланды, Великобритания, Бельгия, Австрия) и Восточная (Польша, Чехия, Румыния, Венгрия, Литва, Латвия, Эстония, Болгария, Украина)

Один из маркетинговых каналов продукта — **автонаписание и публикация статей для
рестораторов** (темы: репутация, технологии, реклама в сети для общепита, и другие —
тема каждой статьи исследуется отдельно, список тем не фиксирован). Уже спроектирован
скилл-пайплайн: он сам исследует тему статьи, пишет текст на языке целевого региона,
прогоняет через "антиИИ-стайлинг" (чтобы текст не звучал как сгенерированный), и
выбирает площадку публикации по гео заявки.

**Проблема, которую решает эта задача:** черновой список площадок для публикации
собран "с ходу", без проверки — LinkedIn, Medium, VC.ru, Habr, Telegram, собственный
блог (см. таблицу ниже). Это неполно и не проверено вживую. Нужен целенаправленный
ресерч через WebSearch, а не додумывание.

## Задача

Для **каждого из трёх регионов** (Закавказье, Средняя Азия, Европа — Европу раздели
на Западную/Восточную, там разные площадки) найди реальные площадки для публикации
бизнес-контента, куда реально читают **владельцы ресторанов/кафе и небольшой
локальный бизнес**, а не только IT-аудитория.

Отправная точка примера (не единственный кандидат) — площадки вроде **Яндекс.Дзен**
для русскоязычной аудитории: агрегаторы контента с органическим охватом, а не только
классические блог-платформы или соцсети. Ищи такие же по духу площадки для каждого
региона: локальные аналоги контент-агрегаторов, отраслевые медиа про общепит/ресторанный
бизнес, деловые СМИ с блог-разделами, популярные Telegram-каналы для рестораторов
(как ориентир на охват, не обязательно как площадка публикации), локальные социальные
сети, если они значимы в регионе.

## Что нужно определить по каждой найденной площадке

1. **Название и регион/язык аудитории**
2. **Реально ли это читают рестораторы/владельцы малого бизнеса** (не просто "популярная площадка вообще")
3. **Есть ли публичный API для публикации** (автопост) или это исключительно ручная/редакционная публикация — критично честно проверять через официальную документацию для разработчиков, а не предполагать. Проверь: требует ли публикация одобрения приложения (по духу как Meta App Review), есть ли лимиты/квоты
4. **Тип площадки**: контент-агрегатор с алгоритмической раздачей (как Дзен) / классический блог / деловое медиа / соцсеть / Telegram

## Формат вывода

```json
{
  "id": "platform_id",
  "name": "Человекочитаемое имя",
  "automation_tier": 1,
  "api_notes": "Что именно нашёл про API — конкретно, со ссылкой на источник",
  "regions": ["caucasus"],
  "languages": ["ru"]
}
```

Где `automation_tier`:
- **1** — реальный API, публикует без одобрения приложения
- **2** — API есть, но нужно пройти одобрение разработческого приложения (внешний lead time)
- **3** — только редакционная/ручная публикация, автопоста не существует в принципе

## Как сдать результат

1. Структурированный отчёт по каждому региону: что нашёл, с источниками (ссылками)
2. Итоговый список площадок в формате JSON выше — готовый вставить в реестр целиком
3. Явно помечай любые находки, которые не удалось проверить (например: "площадка существует, но не нашёл документацию API — предполагаю Tier 3 до проверки") — не выдавай предположения за подтверждённые факты
