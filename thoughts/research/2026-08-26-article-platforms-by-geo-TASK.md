# Задача на ресерч: площадки для публикации статей по гео — для Repas

Скопируй этот файл целиком в начало новой сессии Claude Code.

## Контекст проекта

Repas — сервис мониторинга репутации ресторанов/кафе в интернете (карты, отзовики,
доставка, соцсети), сначала бесплатный лид-магнит (разовый отчёт на email), затем
платный SaaS-дашборд. Целевые рынки — **не Россия**:

- **Закавказье**: Грузия, Армения, Азербайджан
- **Средняя Азия**: Казахстан, Узбекистан, Киргизия, Таджикистан, Туркменистан
- **Европа**: Западная (Германия, Франция, Испания, Италия, Нидерланды, Великобритания, Бельгия, Австрия) и Восточная (Польша, Чехия, Румыния, Венгрия, Литва, Латвия, Эстония, Болгария, Украина)

Один из маркетинговых каналов — **автонаписание и публикация статей для рестораторов**
(темы: репутация, технологии, реклама в сети для общепита, и другие — тема
исследуется отдельно под каждую статью). Уже спроектирован скилл
`marketing/article_pipeline/SKILL.md` и черновой реестр площадок
`marketing/article_pipeline/platforms.json` — но туда пока попали только площадки,
которые придумались "с ходу" (LinkedIn, Medium, VC.ru, Habr, Telegram, собственный
блог). **Это неполно и не проверено вживую** — нужен целенаправленный ресерч.

## Задача

Для **каждого из трёх регионов** (Закавказье, Средняя Азия, Европа — Европу можно
и нужно делить на Западную/Восточную, там разные площадки) найти реальные площадки
для публикации бизнес-контента, куда реально читают **владельцы ресторанов/кафе
и небольшой локальный бизнес**, а не только IT-аудитория.

Отправная точка примера (не единственный кандидат) — площадки вроде **Яндекс.Дзен**
для русскоязычной аудитории: агрегаторы контента с органическим охватом, а не только
классические блог-платформы или соцсети. Ищи такие же по духу площадки для каждого
региона: локальные аналоги контент-агрегаторов, отраслевые медиа про общепит/ресторанный
бизнес, деловые СМИ с блог-разделами, популярные Telegram-каналы для рестораторов
(как ориентир на охват, не обязательно как площадка публикации), локальные социальные
сети, если они значимы в регионе.

## Что нужно определить по каждой найденной площадке

1. **Название и регион/язык аудитории**
2. **Реально ли это читают рестораторы/владельцы малого бизнеса** (не просто "популярная площадка вообще")
3. **Есть ли публичный API для публикации** (автопост) или это исключительно ручная/редакционная публикация — критично честно проверять, не предполагать. Проверить: официальную документацию для разработчиков, требует ли публикация одобрения приложения (как Meta App Review), есть ли лимиты/квоты
4. **Тип площадки**: контент-агрегатор с алгоритмической раздачей (как Дзен) / классический блог / деловое медиа / соцсеть / Telegram

## Формат вывода

Результат должен лечь в `marketing/article_pipeline/platforms.json` — сохраняй в
той же структуре, что уже есть в файле:

```json
{
  "id": "platform_id",
  "name": "Человекочитаемое имя",
  "automation_tier": 1,
  "api_notes": "Что именно нашёл про API — конкретно, со ссылкой на доку, если есть",
  "regions": ["caucasus"],
  "languages": ["ru"]
}
```

Где `automation_tier`:
- **1** — реальный API, публикует без одобрения приложения
- **2** — API есть, но нужно пройти одобрение разработческого приложения (внешний lead time)
- **3** — только редакционная/ручная публикация, автопоста не существует в принципе

## Как сдать результат

1. Сохранить итог исследования как `thoughts/research/YYYY-MM-DD-article-platforms-by-geo.md` (формат — как в `.claude/skills/bulletproof/templates/research.md`, если скилл Bulletproof доступен в этой сессии; если нет — просто структурированный список находок по каждому региону с источниками)
2. Предложить итоговый список площадок в формате JSON выше, готовый к вставке в `marketing/article_pipeline/platforms.json`
3. Явно пометить любые находки, которые не удалось проверить (например, "площадка существует, но не нашёл документацию API — предполагаю Tier 3 до проверки") — не выдавать предположения за подтверждённые факты
